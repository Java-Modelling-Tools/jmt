Installation notes

It is recommended to UNINSTALL any previous version of Java Modelling Tools present on your PC before installing this new release.

What’s new? JMT release 1.5.1

14 November 2026

JABA

  • Fixed the graphs not being drawn after solving a model (Convex Hull and Performance Indices tabs). The computed values were correct, only the graphs were missing.

JSIM

  • Fixed loading of .jsimg archives: only the simulation part is read, so classes are no longer duplicated, the seed, maximum time and maximum samples are honoured, and open_1class_3stat_fork and open_1class_3stat_advfork open correctly.
  • A missing, empty or malformed model or results file is now reported as a failed load instead of throwing an exception.
  • A failed archive save is now reported instead of being shown as successful.
  • Fixed the rotation and angle of a station leaking to the next station when a model is loaded.
  • Set-up and delay-off distributions and the scheduling policy of servers are kept when a model is saved and reloaded, and polling servers are saved as valid XML.
  • A results file can now be written for a measure that has no samples, and the results of an engine run no longer take the mean as last-interval value and simulation time.
  • Model checker: an open class without a sink is now reported when the model has a server, the unpredictable-service check now looks at the first class, a closed model with zero total population is shown as a warning instead of an error, and deleting a server type also removes the measures that refer to it.
  • Converting a model with priority scheduling to JMVA now warns about it and lists the stations.
  • PNML import and export now work on JDK 11 and later.

Distributions

  • Gamma distribution: the theoretical mean, variance and cdf now use lambda as scale, as the sampler and the pdf already did. Models using a Gamma distribution can show different theoretical values than in 1.5.0.

Logging

  • SLF4J is now the only logging API and log4j 2 the only backend. log4j 1.2, logback and java.util.logging are removed. The rolling JSIM.log file is kept and the level can be set with -Djmt.log.level.
  • Logging no longer stops for the rest of the session after the first PNML import or export.

Architecture

  • The simulation engine no longer depends on Swing: popups go through a small error-reporter interface and delayed warnings through a single helper.
  • First stages of the separation between model and view in the GUI, with no change in behaviour.

Build and tests

  • Many more unit tests for the engine, the file handler, the JMVA core and the GUI model.
  • The integration-test suite now logs through SLF4J, has opt-in coverage, a reliable timeout and progress output.
  • Javadoc is generated for all modules and published on the website.
  • Added a release checklist.

What’s new? JMT release 1.5.0

2 November 2026

Architecture

  • JMT is no longer a single monolithic module. It is now a 16-module Maven project with a strict layering (engine, GUI, file handler, solver cores, tool GUIs, application), and a headless integration-test harness.
  • New jmt-legacy-xml module: each saved archive is accompanied by a legacy copy that releases up to 1.4.0 can still open, and the JMT version is recorded in the file.
  • JMT now warns before opening a file saved by a newer version.
  • Added CONTRIBUTING.md (architecture, module layers, ownership) and GitHub issue templates.

JSIM

  • Added a visual debug tracer, with compression and event filtering. It can be triggered both from the jar and from the command line.
  • Fixed a dispatch failure in the load-dependent routing strategy and a spurious routing warning at simulation start.
  • Fixed XML serialization of multiserver stations, and the station's server count is now written in the default server type.
  • What-if analysis now uses the same simulation seed for every step, so steps are comparable.
  • Fixed an exception on microsecond service times (spinner lower bound).
  • Fixed a NullPointerException when closing a model, and several rendering exceptions in the GUI.
  • Simulation speed-ups: faster entity lookup and no unnecessary synchronization in the per-simulation system methods.
  • A queue now ignores a job-finish event when it has no pending place request.

Build and tests

  • The installer is now staged and built after the single jar exists (IzPack updated to 5.2.4).
  • Packaged jars are all written to ./target.
  • The integration-test suite has configurable timeout and result-comparison (SMAPE) tolerance, a utilization checker, and a reorganized test directory.
  • 12 priority/SCA paper-comparison tests in the JMVA core are marked as ignored: they could not run before and their assertions are too strict for the solvers' tolerances (tracked for follow-up).

Working folder


A JMT working folder will be created in the home directory of the user to store examples and working files. For example, the files created by the Loggers (xxx.csv files) are by default located in this folder. The location of the working folder depends on the operating system:
  • Linux: /home/<user name>/JMT
  • Windows: C:\Users\<user name>\JMT
  • Mac OS X: /Users/<user name>/JMT
In older JMT versions, the default working folder was the JMT installation path.
